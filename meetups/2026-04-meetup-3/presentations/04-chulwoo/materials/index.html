E핵심 주장
01
Thesis

LLM Wiki는 "검색 도구"가 아니라 지식 컴파일 워크플로우다.

기존 RAG

질문할 때마다 raw source를 검색하고, chunk를 모아, 그 자리에서 다시 합성한다.

LLM Wiki

소스를 읽을 때 먼저 wiki로 컴파일하고, 다음 질문은 이미 정리된 구조에서 시작한다.

차이

답변이 채팅 로그에서 사라지지 않고, 다음 탐색을 위한 durable artifact가 된다.

주의

모든 지식에 맞는 방식은 아니다. 정확한 숫자와 계약은 raw source로 다시 검증해야 한다.

컴파일 시점이 바뀌면 비용, 정확성, 운영 방식이 같이 바뀐다.

E3 Layer Architecture
03
Architecture

raw source, wiki, schema: 세 레이어가 역할을 나눈다.

raw/ 원문, 논문, 이미지, 로그. LLM이 읽지만 수정하지 않는 source of truth.
→
wiki/ LLM이 유지하는 markdown 지식층. entity, concept, synthesis, comparison.
→
answers 질문 답변, 표, 슬라이드, 그래프. 좋은 답변은 다시 wiki에 저장.

Ingest
새 소스를 읽고 관련 페이지 10-15개를 업데이트한다.

Query
index를 보고 관련 페이지에서 답하고, 좋은 분석은 저장한다.

Lint
모순, stale claim, orphan page, missing link를 점검한다.

Obsidian is the IDE. The LLM is the maintainer. The wiki is the codebase.

ELLM Wiki v2
05
Critical Update

v2의 핵심: wiki가 썩지 않도록 지식의 lifecycle을 설계한다.

Confidence

각 claim이 몇 개의 source로 지지되는지, 얼마나 최근에 확인됐는지 점수화한다.

Supersession

새 정보가 이전 claim을 대체하면 old claim을 지우지 않고 stale로 연결한다.

Forgetting

모든 정보를 영원히 동일하게 보지 않는다. 접근과 재확인에 따라 우선순위가 바뀐다.

Memory Tiers

working, episodic, semantic, procedural memory로 관찰을 점점 압축한다.

원본이 "지식을 컴파일하자"였다면, v2는 "컴파일된 지식을 어떻게 신뢰할 것인가"에 답한다.

ECritical Takes
08
Failure Modes

커뮤니티가 지적한 위험은 꽤 실전적이다.

Lossy Compile

ingest 시점에 summary가 숫자, 조건, 예외를 잃으면 wiki는 보기 좋지만 틀린 지식층이 된다.

Lint Blind Spot

lint가 wiki끼리의 일관성만 보면 원문과의 불일치를 못 잡는다.

Not Always PKM

LLM이 글을 쓰면 "내 생각"이라기보다 내가 읽은 외부 지식의 research index에 가깝다.

Team Scale

여러 agent와 사람이 동시에 쓰면 attribution, conflict, ownership 규칙이 필요하다.

Stale Graph

코드나 설계가 바뀌었는데 graph/wiki가 업데이트되지 않으면 두 번째 source of truth가 된다.

Schema Drift

schema가 약하면 LLM이 상태값, 태그, 파일명을 매번 새로 invent하면서 지식층이 흐트러진다.

핵심: wiki를 source of truth로 착각하지 말고, chain of custody를 유지해야 한다.

ESchema First
10
The Schema Is The Product

진짜 제품은 wiki가 아니라 AGENTS.md다.

wiki는 output이다. schema는 LLM에게 어떤 지식 구조를 만들고, 어떤 품질 기준으로 유지할지 알려주는 compiler spec이다.

Schema Checklist
  • entity type과 relationship type 정의
  • source별 ingest policy: 논문, datasheet, 회의록, 실험 로그
  • 새 페이지 생성 vs 기존 페이지 업데이트 규칙
  • citation, confidence, provenance frontmatter
  • 숫자, 날짜, 법적 문구는 raw source 검증
  • conflict, supersession, stale claim 처리 규칙
  • lint 주기와 자동 수정 범위
Schema가 약하면 LLM이 매번 자기만의 wiki 문법을 만든다.

EProduct Concept
17
One-Sentence Spec

책상 위 세 마리 피규어가 Claude Code 세션을 한 마리씩 담당한다.

어느 세션이 뭘 하는지 LED 눈으로 보여주고, 입력이 필요하면 물리적으로 뽁 튀어오르고, 머리를 누르면 그 세션에 승인 신호가 전송된다.

Evolution 1

1마리 → 3마리

병렬 세션을 동시에 굴리는 파워유저를 위한 multi-agent dock.

Evolution 2

눈 없음 → LED 눈

idle, thinking, waiting, done, error를 색과 리듬으로 구분.

Evolution 3

단방향 → 양방향

머리를 톡 누르면 해당 세션에 Enter. 키보드로 창 전환할 필요 없음.

타겟: Claude Code 멀티세션 파워유저. 귀여움과 실용성의 균형.
ECore Functions
18
What It Does

한 솔레노이드, 두 LED 눈, 한 택트 스위치로 다 한다.

Eye Animation

상태 시각화

idle 숨쉬기, thinking 부드러운 깜빡, waiting 빠른 깜빡, done 초록 1회, error 빨강 2회.

Solenoid Pop

알림 리듬

입력 필요 "뽁뽁뽁" 3회, 작업 완료 "뽁" 1회, 에러는 느린 "뽁..." 1회.

Head Press

물리적 승인

튀어오른 피규어 머리를 누르면 세션에 Enter 전송. 시각·청각·촉각이 한 번에.

Auto Mapping

제로 설정

새 세션 시작하면 빈 피규어 한 마리에 자동 할당. USB 꽂고 끝.

"3 is enough" — 4번째 세션이 생기면 LRU로 가장 오래 idle인 피규어를 재할당. 인지 한계를 존중하는 의도된 제약.

의도적 제외: 서보, 스피커, 화면, Wi-Fi, 자이로. 미니멀이 본질.
